# Flipkart Order Intelligence & Support Assistant

## What Is This Project?

This project is a small support system for an online shopping company. It combines three useful abilities:

1. It estimates whether an order is likely to be returned.
2. It recognizes the type of product shown in a product image.
3. It answers return and delivery questions using a policy knowledge base.

The goal is to show how data, machine learning, image recognition, search, and an AI-style support workflow can work together in one connected application. The system uses real generated experiment data and real Fashion-MNIST images. It does not hardcode model predictions or invent evaluation numbers.

## What Happens When It Runs?

An order-risk request goes through this path:

```text
Order details -> return-risk model -> probability -> Low, Medium, or High risk
```

An image request goes through this path:

```text
Product image -> ResNet-18 image model -> product category and confidence
```

A policy request goes through this path:

```text
Question -> relevant policy search -> evidence-based answer
```

The support agent first identifies what the person is asking. It then sends the request to only the required path. For example, a policy question goes to document search, while a return-risk question calls the saved return-risk model. This prevents unrelated tools from being used for the wrong request.

## Why Are These Parts Useful?

- **Return-risk prediction:** Support teams can prioritize orders that may need extra attention. The model reports a probability instead of pretending that every prediction is certain.
- **Product image classification:** A product photo can be mapped to a broad category such as sneaker, bag, shirt, or coat.
- **Policy search:** The assistant answers from stored policy text instead of making up a return window or refund time.
- **Guardrails:** Prompt-injection attempts are blocked, and questions without reliable policy evidence receive a refusal.
- **Conversation memory:** A follow-up question can refer to an order from the same conversation, while a new conversation starts with no old order context.

## How The Project Is Organized

- `generate_orders.py` creates the reproducible order dataset.
- `part1_return_risk/` trains and evaluates the return-risk model.
- `part2_product_classifier/` trains and evaluates the image classifier.
- `part3_support_agent/` contains the support agent, tools, retrieval, and guardrails.
- `models/` stores the trained model files.
- `knowledge_base/` stores the policy documents and retrieval results.
- `reports/` stores actual experiment results.
- `transcripts/` stores real agent conversations generated by the scripts.
- `tests/` checks that the main components continue to work.

The command below creates `orders_dataset.csv` and prints deterministic shape and missingness checks:

```powershell
python generate_orders.py
```

## Results In Simple Terms

### Part 1: Order Return Risk

The experiment used 6,000 orders. About 22.75% were returned. The model achieved a held-out ROC-AUC of 0.61755. Its selected Random Forest threshold, called `t*_rf`, is 0.47. This threshold is used to create the support tool's risk buckets:

- Low: probability below 0.47
- Medium: probability from 0.47 up to 0.62
- High: probability at least 0.62

The missing customer-rating values were classified as MAR because the missing rate depended on the observed payment method. COD orders had a 22.83% missing rate, while non-COD orders had a 6.06% missing rate.

The simple majority baseline had 78.08% accuracy but zero F1 for returned orders. This shows why accuracy alone can be misleading when most orders are not returned.

### Part 2: Product Image Recognition

The image model learned from Fashion-MNIST. The 60,000 training images were divided into 55,000 training images and 5,000 validation images. The separate 10,000-image test set was kept untouched until final evaluation.

The model used a pretrained ResNet-18. It first cached features from the frozen image backbone and trained a smaller classifier head. Stage A reached 91.74% validation accuracy, so late-layer fine-tuning was not needed. Final test accuracy was 90.83%.

### Part 3: Support Assistant

The agent searched 12 policy documents with the local `all-MiniLM-L6-v2` embedding model and FAISS. Across five retrieval queries, average Precision@3 was 0.400 and average Recall@3 was 1.000. Nine real transcripts cover policy questions, return risk, image classification, prompt injection, unsupported questions, and conversation reset behavior.

## Part 1 Results

The generated dataset contains 6,000 rows and 13 columns. The observed return rate is 0.2275, rating missingness is MAR, and the COD versus non-COD missingness gap is 16.77 percentage points. The DummyClassifier has accuracy 0.78083 and returned-class F1 0.0. Random Forest CV ROC-AUC is 0.61797, held-out ROC-AUC is 0.61755, and the RF-specific threshold `t*_rf` is 0.47.
